# Changelog

All notable changes to this package are documented here.

## Unreleased

### Added

- `vite-shopify-theme dev` and `dev --editor` print a short header (mode, Vite, Shopify CLI, and Node versions, store and environment) before starting and a `Stopped.` line after both processes exit, naming what was left behind. Colors only on an interactive terminal; plain text under `CI`, `NO_COLOR`, or a pipe. `--raw` prints only Vite and Shopify CLI output as before. Shopify CLI output, prompts, and keyboard shortcuts are untouched ([RFC 0003](docs/rfcs/0003-terminal-output.md), part 1).
- A `━━ Shopify CLI ━━━━` rule marks where Shopify CLI's output begins, and watch builds (`dev --editor` or `vite build --watch`) print one line each: `[shopify-theme] build ok · 2 entries · 312 ms · snippet written` or `snippet unchanged`, and `build failed · keeping the last good output` after a failed build. In editor mode, a hint appears when `.gitignore` lacks the generated-file patterns that make Tailwind CSS rebuild in a loop (RFC 0003, part 2).

## 0.6.1

### Changed

- Entry scripts are emitted as `theme-<hash>.js` instead of `theme.ts-<hash>.js`: the script extension of the entry key is dropped from the output file name. The key, the `render ... entry:` name, and the manifest are unchanged. The next build writes the new names into the snippet and removes the old files as stale, because they are recorded in the ownership state.
- `init` on a theme that already has its own Vite config no longer generates a config or scaffold entries, edits layouts, replaces `build` and `dev` scripts, or installs TypeScript and Tailwind. It adds the plugin, the `dev:editor` script, ignore patterns, and the example environment file, then prints the remaining manual steps. A config generated by an earlier `init` still counts as generated, so reruns stay idempotent.

### Documentation

- Corrected how to reference manual `assets/` files from CSS: URLs in a partial in a subfolder need the `../` path to the entry's folder, otherwise the built stylesheet points to a folder that does not exist.
- Added a troubleshooting entry for endless rebuilds under `dev:editor` and `vite build --watch` when `.gitignore` lacks the generated-file patterns that `init` writes. The entry states that the hashed assets are what retrigger the build.
- Documented that npm 10.8.2, bundled with Node.js 20.19.0, cannot install Vite 8.2 or newer (`edgesOut` error, upstream npm bug), and how to avoid it. The compatibility matrix upgrades npm for that one job.

## 0.6.0

### Added

- `vite-shopify-theme dev --editor` (script `dev:editor`) gives live updates in the Theme Editor without a tunnel or any external tool. It runs `vite build --watch`, waits for the first successful build, then starts `shopify theme dev` with `--live-reload full-page` unless you choose a live-reload mode. HMR stays the default `dev` mode.
- In watch mode the plugin holds one ownership lock for the whole session, writes the snippet shortly after the assets it references, keeps the previous build's assets for one more build before deleting them, and keeps the last working output after a failed build.
- `init` adds a `dev:editor` package script when the project does not define one.
- Documented when to choose each development mode in the development modes guide, the Theme Editor cookbook page, and the agent instructions.

## 0.5.2

### Fixed

- `vite build --watch` no longer rebuilds endlessly. The generated snippet is written only when its content changes, so tools that scan the theme, such as Tailwind, no longer see a new file after every build.

## 0.5.1

### Added

- `vite-shopify-theme dev` now selects the Shopify CLI `development` environment automatically when `shopify.theme.toml` defines `[environments.development]`, and forwards arguments after `--` to `shopify theme dev`.
- `init` writes `example.shopify.theme.toml` (never overwriting an existing file) and ignores `shopify.theme.toml` in git.
- Documented the Shopify `Upload Errors` caused by a reused development theme in the troubleshooting guide.

## 0.5.0

### Added

- Entries now accept an object form, `{ source, attributes?, inline? }`, alongside the string form. `attributes` adds sorted, HTML-escaped attributes to the entry's `<script>` and stylesheet `<link>` tags. `inline: true` renders a stylesheet entry with Shopify's `inline_asset_content` filter in production. Invalid options fail at configuration time with `CONFIG_ENTRIES`. The `EntryOptions` type is exported.
- Added the `INLINE_CSS_TOO_LARGE` warning: an inline stylesheet of 15,000 bytes or more falls back to a `<link>` tag instead of failing the build, because Shopify only inlines files under 15 KB.
- Added the `SNIPPET_SIZE_NEAR_LIMIT` warning when a generated snippet reaches 75% of Shopify's 256 kB limit.
- Added `DEV_ORIGIN_UNAVAILABLE` for development servers without an HTTP server or already listening, such as middleware mode.
- Documented the setup checklist, Theme Editor with a tunnel, fonts, images and vendors, page-specific stylesheets, critical CSS, and agent instructions with a copyable `AGENTS.md`.
- Added RFC 0002 for tag attributes and inline CSS.

### Fixed

- Fixed the development server answering every origin with the tunnel origin when `devOrigin` is set. It now allows localhost, the tunnel origin, `https://*.myshopify.com`, and `https://*.shopify.com`.
- Fixed lock reclaim so it re-reads the owner token before removing a stale lock, and treats a lock owned by another host as live.
- Stale asset cleanup now records the union of old and new assets before deleting, and atomic writes flush to disk before renaming.
- Failure to read the theme root now reports `CONFIG_THEME_ROOT`, and a missing manifest entry uses one shared diagnostic.

## 0.4.2

### Fixed

- Fixed first-run `bun dev` failing with `Could not find asset snippets/vite-tag.liquid`: `dev` now starts Shopify CLI only after Vite has written the development snippet.
- `init` now creates a placeholder `snippets/vite-tag.liquid` (never replacing an existing one), so a new theme renders without errors before the first build or `dev`.
- Removed the cloned Skeleton git history from new themes created by `init`.

### Changed

- `init` no longer installs Shopify AI Toolkit skills; they are documented in the cookbook. `--no-skills` is accepted and ignored, and `--skills` was removed.

## 0.4.1

### Fixed

- Fixed `init` failing to create a new theme because `shopify theme init --latest` cannot clone releases shallowly; new themes now clone the pinned Skeleton `v1.0.0` release.
- Fixed `init` generating a `package.json` without `"type": "module"`, which made Vite fail to load the ESM-only plugin from `vite.config`.
- Fixed `init` writing `.shopifyignore` directory patterns (`node_modules/`, `frontend/`) that Shopify CLI warns about; it now writes `node_modules/*` and `frontend/*`.

### Changed

- `init` language and package manager prompts are now selectable with the arrow keys in interactive terminals.

## 0.4.0

### Added

- Added the public `vite-shopify-theme init` wizard for conservative setup of new Shopify Skeleton projects and existing themes, with TypeScript, Tailwind, and Shopify AI Toolkit defaults.
- Added `vite-shopify-theme dev` to coordinate installed Vite and Shopify CLI processes.
- Added a VitePress documentation site and GitHub Pages deployment workflow.
- Accepted the scoped 0.4.0 CLI RFC; tunnel management and deployment remain out of scope.
- Added stable, searchable diagnostic codes to every plugin-authored error and warning, with a documented code reference for troubleshooting.
- Added opt-in `diagnostics` lifecycle logging through Vite's logger, including stable events for configuration, ownership, build output, development restoration, and hot reloads.
- Added early `THEME_STRUCTURE_INVALID` diagnostics for missing or non-directory Shopify assets and configured snippet directories.
- Documented supported monorepo and multi-theme config topologies and added concurrent isolation coverage for independent theme roots.
- Added boundary-first troubleshooting guidance that separates Vite/plugin, Shopify, and tunnel/browser failures with concrete file, command, HTTP, and WebSocket checks.

### Changed

- Made the default `shopify` import canonical in documentation and examples while preserving the identical `shopifyTheme` named export.

## 0.3.0

### Added

- Added canonical real-path enforcement for symlinked theme roots, entries, generated snippets, assets, ownership state, locks, manifests, and development recovery.
- Added large-manifest, repeated crash-recovery, high-volume cleanup, and symlink-policy coverage.
- Added Linux, macOS, and Windows canonical CI, npm 10.8.2/latest packaging checks, and packed-package consumer builds with npm, pnpm, Yarn, and Bun.
- Added an approval-protected, manual Shopify end-to-end workflow for `main`.

### Changed

- Replaced recursive manifest traversal with deterministic iterative traversal for deeply nested and cyclic graphs.
- Unified npm Trusted Publishing and GitHub Release creation in the protected tag-driven workflow, including integrity-safe reruns.

## 0.2.1

### Added

- Documented official Vue and React composition recipes, including React Fast Refresh setup for Shopify-rendered HTML and independently mounted section applications.
- Documented the supported module-preload, asset-versioning, and provider-agnostic HTTPS tunnel policies without adding runtime dependencies or public APIs.
- Added network-dependent Vue 3 and React 19 compatibility fixtures covering production builds, generated manifests and snippets, development module serving, React's preamble, and snippet restoration.

### Changed

- Renamed the public package to `@display-studio/vite-plugin-shopify-theme` and aligned its repository metadata with the `display-design-studio` GitHub organization.
- Restricted Liquid-facing entry names to `[A-Za-z0-9][A-Za-z0-9._-]*` so generated case branches cannot be altered by quotes, whitespace, path separators, or Liquid syntax.
- Closed the P4 interoperability evaluation with framework composition, preload/versioning, and externally managed tunnel decisions that preserve the plugin's focused ownership boundary.

## 0.2.0

### Breaking changes

- Replaced the `entry` option with the required `entries` map. Entry names are now explicit and are the values passed to the generated Liquid snippet.
- Removed the `shopify-theme` executable and its legacy CLI options. Development now uses Vite and Shopify CLI as separate processes.
- Made `themeRoot` the boundary for entry resolution, generated snippets, Shopify assets, ownership state, and process locking.
- `shopifyTheme()` now accepts the explicit configuration documented in the README and returns one Vite plugin rather than a plugin array.
- The package is ESM-only, has zero runtime dependencies, and exposes only its root entrypoint.
- Supported Node.js versions are now `^20.19.0 || >=22.12.0`, matching the Vite 8 requirement.

### Added

- Deterministic production snippets, development HMR and theme reload support, plugin-owned asset cleanup, locking, and crash recovery.
- Package-contract validation for published files, metadata, exports, types, installation, and blocked internal subpaths.
- Canonical CI on Node.js 24 and separate Vite/Shopify CLI compatibility coverage.
